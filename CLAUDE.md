# CLAUDE.md

Правила работы с репозиторием Persona.

## Проект

- Проект называется **«платформа управления портфелем аккаунтов»** (Persona — account portfolio
  management platform).
- Нельзя использовать в коде, комментариях, документации, коммитах и названиях сущностей формулировки:
  - «ферма аккаунтов»;
  - «обход детекции»;
  - «имитация поведения»;
  - «фейковые люди».

## Границы

- Акторные реализации платформ, приватные API, браузерная автоматизация и техники обхода ограничений
  **не проектируются и не реализуются**.
- Интеграции с внешними платформами (Instagram, TikTok, X, Telegram и т.п.) не входят в текущий объём.

## Текущий фокус

- доменная модель;
- стейт-машина жизненного цикла аккаунта;
- события жизненного цикла;
- политики как конфигурация (данные, а не код);
- абстрактные интерфейсы (контракты хранения без реализаций).

## Технические правила

- Стек: Node.js 20+, TypeScript 5.x (strict), ESM, pnpm workspaces, Turborepo, ESLint + Prettier, Vitest.
- `packages/core` самодостаточен: никаких runtime-зависимостей, никакой сети, БД, Redis, очередей и HTTP —
  только чистая доменная логика.
- Доменные функции валидируют входные данные и бросают типизированные ошибки (`DomainError` и наследники).
- Состояния не мутируются: функции возвращают новые объекты.
- Перед завершением работы должны проходить: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
